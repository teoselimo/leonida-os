# LEONIDA OS V0.5 — Veille autonome

## 1. Diagnostic et choix d'hébergement

| Constat | Conséquence |
|---|---|
| Le frontend V0.4 est un export statique (`output: "export"`) | Il ne peut pas porter de cron ni de routes serveur |
| La page publiée sur claude.ai bloque tout appel réseau vers un autre domaine | Elle ne pourra jamais lire une base ou un flux externe : elle reste une maquette |
| Rockstar Newswire : ni RSS, ni sitemap, ni API publique ; rendu JavaScript ; `robots.txt` interdit les robots d'IA | Pas de collecte Newswire (pas d'API interne non documentée). Les annonces officielles sont suivies via **le flux Atom public de la chaîne YouTube Rockstar Games** |
| Polygon renvoie HTTP 403 à notre robot identifié | Refus respecté : source désactivée |

**Retenu pour la V0.5 (gratuit, actif sans intervention) :**

```
GitHub Actions (cron toutes les 15 min, côté serveur)
   └─ collector/ : collecte → tri → analyse → validation → publication
        └─ commit de radar.json sur la branche `data`
GitHub Pages : frontend V0.4 (inchangé côté UX)
   └─ lit https://raw.githubusercontent.com/teoselimo/leonida-os/data/radar.json
      au lancement, puis toutes les 10 min et à chaque retour au premier plan
```

Une nouvelle fiche apparaît donc **sans redéployer le site** : seul le fichier de données change.

**Cible V1 : Supabase.** `collector/sql/001_schema.sql` contient les tables du brief, les règles d'accès (RLS : lecture publique bornée, écriture réservée au service) et des contraintes de sécurité (pas de coordonnées sans validation ; pas de « personal » côté serveur ; miniatures uniquement hébergées par YouTube). Le schéma a été testé sur un Postgres embarqué. La logique du pipeline ne dépend pas du stockage : il suffit de remplacer `store/fileStore.ts`.

## 2. Ce qui tourne réellement

| Connecteur | État | Accès |
|---|---|---|
| Rockstar Games (YouTube officiel) | **Actif**, toutes les 15 min | Flux Atom public, sans clé. Jamais envoyé à une IA |
| GTA Series Videos (YouTube) | **Actif**, 30 min | Flux Atom public |
| Rockstar Intel, GTA BOOM, PC Gamer, GamesRadar+ | **Actifs**, 60 min | Flux RSS publics : titre, date, lien, extrait ≤ 280 caractères |
| YouTube Data API v3 (recherches ciblées) | **Prêt, inactif sans clé** | Secret `YOUTUBE_API_KEY` |
| Reddit r/GTA6 | **Prêt, inactif sans autorisation** | Secrets `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET` ; variable `REDDIT_USER_AGENT` |
| Enrichissement IA (traduction FR, résumé) | **Prêt, inactif sans clé** | Secret `ANTHROPIC_API_KEY` ; variable `ANTHROPIC_MODEL` |
| Rockstar Newswire | **Non supporté**, volontairement | Aucun accès public conforme |
| Polygon | **Désactivé** | Refus HTTP 403 respecté |

Une source en panne n'arrête pas les autres. Chaque requête a 3 tentatives, avec un recul exponentiel. Après un échec, la source est mise en pause de plus en plus longtemps (×2, ×4… jusqu'à 6 h). L'état de chaque source est visible dans l'app (Radar › Veille automatique) et dans le résumé de chaque exécution GitHub Actions.

## 3. Pipeline

1. **Collecte** : un connecteur par source, déclaré dans `collector/sources.json`. Ajouter une source ne touche pas au cœur.
2. **Tri** (règles déterministes, EN/FR) :
   - écarte ce qui est hors sujet, GTA V/Online, Red Dead, les montages, réactions, mods et memes ;
   - écarte les contenus de plus de 21 jours ;
   - repère les doublons : même URL canonique, même ID de vidéo ou titres très proches dans la même catégorie.
3. **Analyse** :
   - classe dans une catégorie : arme, véhicule, argent, easter egg, mission secondaire, objet unique, mécanique, manquable, guide, actualité, mise à jour ;
   - détecte les spoilers ;
   - extrait un montant ou une mention « manquable » **seulement s'ils sont cités textuellement** (la citation est conservée) ;
   - repère un lieu cité (nom de lieu gtadb d'au moins deux mots, ou nom de région officiel), en texte seulement.
4. **Validation** :
   - `official` : uniquement si une preuve vient de Rockstar ;
   - `confirmed` : au moins 2 preuves **indépendantes** (aucune origine commune : deux sites relayant la même vidéo comptent pour une), contenu actionnable et précis, sans marqueur de rumeur ;
   - `rumor` : fuite, théorie, « reportedly », titre interrogatif, ou source à faible confiance seule ;
   - `reported` : tout le reste ;
   - le statut (`active / disputed / outdated / retracted`) est indépendant de la fiabilité. Les raisons du classement, les preuves avec citations et l'historique des révisions sont conservés.
5. **Enrichissement** :
   - miniature YouTube affichée depuis `i.ytimg.com`, créditée, avec un lien vers la vidéo ;
   - aucune image d'article n'est republiée ;
   - **aucun point sur la carte sans validation administrateur**.
6. **Personnalisation** (dans l'app) :
   - le Radar est commun, filtré par l'anti-spoiler du joueur ;
   - seules les fiches officielles ou confirmées, actionnables et localisées par un point validé deviennent des découvertes (carte, « Que faire maintenant ? ») ;
   - le reste va dans Radar › À vérifier.
7. **ViceScopeIV** : une note d'opportunité vidéo (nouveauté, intérêt, visuel, testabilité, concurrence, certitude) et des brouillons de Shorts. L'angle est « vrai ou faux ? » tant que l'info n'est pas établie. Rien n'est publié automatiquement.

## 4. Corrections administrateur (sans redéploiement)

Modifier `collector/overrides.json` directement sur GitHub. La correction est appliquée à la collecte suivante, puis tracée dans l'historique de la fiche.

```json
{ "items": {
  "r-1a2b3c4d5e": { "status": "retracted", "note": "infirmé en jeu" },
  "r-6f7a8b9c0d": { "location": { "regionId": "keys", "place": "Permit Keys", "x": -2100, "y": -5300 } }
} }
```

L'identifiant de la fiche est affiché dans l'app (Radar › Détails).

## 5. Variables et secrets (Settings › Secrets and variables › Actions)

| Nom | Type | Rôle |
|---|---|---|
| `YOUTUBE_API_KEY` | Secret | Active les recherches YouTube ciblées |
| `YOUTUBE_DAILY_UNITS` | Variable | Budget quotidien (défaut 3000 sur 10 000 gratuits) |
| `REDDIT_CLIENT_ID` / `REDDIT_CLIENT_SECRET` | Secrets | Accès Reddit OAuth (app « script » ou « web » approuvée) |
| `REDDIT_USER_AGENT` | Variable | ex. `web:leonida-os:0.5 (by /u/votre_pseudo)` |
| `ANTHROPIC_API_KEY` | Secret | Enrichissement IA optionnel |
| `ANTHROPIC_MODEL` | Variable | Modèle utilisé (obligatoire si la clé est fournie) |

Aucune clé n'est présente dans le code ni dans le site publié.

## 7. Limites réelles

- **Cron GitHub** : jusqu'à 15 min de retard possible aux heures chargées ; GitHub suspend les crons d'un dépôt sans activité pendant 60 jours (relance d'un clic).
- **Cache** : `raw.githubusercontent.com` met le flux en cache environ 5 minutes ; une nouveauté apparaît donc 0 à 25 min après sa publication.
- **Analyse par règles** : prudente, mais imparfaite. Les titres restent en langue originale sans clé IA, et les doublons entre langues ne sont détectés que s'ils partagent une vidéo ou une URL.
- **Vidéos** : seules leurs métadonnées (titre, description) sont lues. Aucune vidéo n'est regardée : une vidéo reste un signal à vérifier tant que d'autres preuves ne la recoupent pas.
- **Rockstar Newswire** : pas de collecte directe, faute d'accès public conforme.
- **Maquette claude.ai** : n'est pas reliée au flux, par construction. L'application vivante est l'URL GitHub Pages.

## 9. Lancer en local

```bash
cd collector && npm ci
npm test                                   # 15 tests du pipeline
npx tsx src/cli.ts --diagnose              # interroge toutes les sources, n'écrit rien
npx tsx src/cli.ts --data ../data-branch   # collecte réelle vers un dossier local
```
